# SSH in Session Deck, Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saved and throwaway SSH connections in the deck, each running in tmux on the Mac, shown in a live terminal, in an SSH section of the menu, with password or key sign-in and single-file send and receive.

**Architecture:** `server.py` gains a host store, `ssh` sessions in tmux (one tmux session per connection, one shared `ControlMaster` per host), and a WebSocket endpoint that bridges a pty running `tmux attach` to xterm.js in the page. The same live terminal replaces the snapshot Terminal view of local chats. `router.py` passes WebSocket upgrades through. Stage 2 (Claude over SSH) gets its own plan once this lands.

**Tech Stack:** Python 3 stdlib (`pty`/`os.openpty`, `fcntl`, `termios`, `socket`), tmux 3.x, OpenSSH, xterm.js 5.5.0 + addon-fit 0.10.0 (vendored), plain JS in `index.html`. Tests: `unittest`, run with `/opt/homebrew/bin/python3 -m unittest discover -s tests`.

**Spec:** `docs/superpowers/specs/2026-11-17-ssh-design.md` (read it first; this plan implements its Stage 1 and the Files section).

## Global Constraints

- One `server.py`, one `index.html`, no build step; vendored libraries in `vendor/`; stdlib `ThreadingHTTPServer`; no new Python dependency.
- Every new endpoint needs `self.authed()` (passkey session over Tailscale, else the local token). The WebSocket also checks `Origin` (see Task 4).
- A password is never written to disk on the Mac, never on a command line (`ps`), never in a log line or push.
- Host keys are never accepted silently: no `StrictHostKeyChecking=no`/`accept-new` added by the deck.
- SSH terminals and their tmux sessions never appear in `live_sessions()` (Active, History, Projects); local chats never appear in the SSH section.
- Nothing is installed on the server. Remote commands use only POSIX `sh`, `mkdir`, `cat`, `find`, `wc`.
- New hosts' Claude permission default is `"default"`; the field is stored now (Stage 2 uses it).
- Copy in the UI: British English, no em dashes, plain words (house style of the existing page).
- Lean code: match the file's existing dense style; no new abstractions beyond those named here.

## Change from the spec (flag to the owner at hand-off)

The spec said passwords reach `ssh` through `SSH_ASKPASS`. This plan instead has the deck type the saved password into the
terminal when OpenSSH's own password prompt appears, once per connect, through `tmux load-buffer -` (stdin) and
`paste-buffer -d`. Reason: with `SSH_ASKPASS_REQUIRE=force`, OpenSSH also routes the first-contact host-key question
through askpass, where the user can't see or answer it; typing into the terminal leaves OpenSSH's own fingerprint prompt
and changed-key refusal in front of the user, which is exactly the spec's host-key behaviour, and works through
`ProxyJump`. The password still never touches disk, argv or logs.

## Review Focus

1. An address like `-oProxyCommand=…` or `host; rm -rf ~` must be refused, never reach `ssh` as an option or shell text (Task 1 test).
2. A phone that locks or loses signal mid-view drops the WebSocket without a close frame: the tmux client, pty and any viewer session must go, and the connection itself must keep running (Task 4 test).
3. Viewing a local chat's terminal must not change which window the MacBook's tmux client shows in session `work` (Task 4 test).
4. A wrong saved password, or a remote program printing `password:` later, must not make the deck type the password again (Task 3 test).
5. Multi-byte UTF-8 split across pty reads or WebSocket frames, and large pastes, pass through byte-exact (Task 4 test).

**Interfaces:**
- Produces:
  - `SSH_HOSTS: Path` = `os.environ.get("DECK_SSH_HOSTS")` or `PREFS.with_name("ssh-hosts.json")`

Host matches `[A-Za-z0-9][A-Za-z0-9.-]{0,252}` or a bracketed IPv6 `[0-9A-Fa-f:.]+`; user matches `[a-z_][a-z0-9_.-]{0,31}`; port 1-65535. New `id` = `secrets.token_hex(6)`. Max 200 hosts. File written 0600 atomically, as `prefs_change` does, under its own lock.
  - `ssh_host_delete(hid: str) -> None`
  - `GET /api/ssh/hosts` -> `{"hosts": [...], "config": ssh_config_names()}`; `POST /api/ssh/hosts` with `{"save": {...}}` -> `{"host": {...}}` or 400 `{"error"}`; with `{"delete": id}` -> `{"ok": true}`.
