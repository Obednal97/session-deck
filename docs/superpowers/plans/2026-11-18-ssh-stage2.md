# SSH Stage 2 (Claude over SSH) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Claude Code chat running on a server over SSH is a full deck chat (transcript, questions, approvals, status, diffs, subagents, rename, end, notifications, git changes, `@` files, uploads, files in replies, history), listed only in the SSH section.

**Architecture:** A remote chat is an SSH connection session (Stage 1's `ssh-<hid>-<n>` tmux session on the Mac) whose pane shows Claude, so everything that reads or types into the pane works unchanged. The transcript and its subagent files are mirrored into a local cache folder by appending only the new bytes over the host's shared connection; every existing reader (`messages`, `info`, `agents`, `image`, `full_tool_diff`) then runs on the mirror. Git, `@` file lists, uploads and files named in replies take a `host` and run over `ssh_run`.

**Tech Stack:** Python 3 stdlib (`server.py`), vanilla JS (`index.html`), OpenSSH, tmux, POSIX `sh` on the server.

**Spec:** `docs/superpowers/specs/2026-11-17-ssh-design.md` (sections "Claude over SSH", "Files", "Order of work" item 2). Stage 1's plan, `docs/superpowers/plans/2026-11-18-ssh-stage1.md`, describes the SSH layer this builds on.

## Global Constraints

- One `server.py`, one `index.html`, no build step, stdlib only, no new vendored library.
- Every new endpoint needs `self.authed()`; host ids go through `ssh_host()`, panes through `valid_pane()` or `valid_term()`.
- Nothing is installed on the server. Remote commands use POSIX `sh` tools only (`cat`, `head`, `tail`, `wc`, `find`, `mkdir`, `grep`, `kill`, `ls`), plus `git`, `tmux` and Claude Code where the server already has them. Every server path or id from the page reaches the shell through `rpath()` or `shlex.quote()`.
- Remote chats and their terminals never appear in `live_sessions()` (Active, Pinned unless pinned, History, Projects); local chats never appear in the SSH section.
- A password is never written to disk, argv, a log line or a push (unchanged from Stage 1).
- Remote reads use the host's shared connection in batch mode (`ssh_run`), so a host with no live master fails at once (exit 255), never prompts, never hangs the page or the watcher.
- Permission mode: the host's `perm` is the default in the new-chat sheet; new hosts are `"default"`; `PERMS` is the only allowed set.
- Copy: British English, no em dashes, plain words, the page's existing style. Lean code: match the file's dense style; no abstractions beyond the ones named here.
- Tests never touch the real tmux servers (`ssh`, `default`), ports 8787/8788/8797, the real `~/.ssh` or a real server: they use the `decktest` socket, `tests/fake_ssh.sh` / `tests/fake_ssh_run.sh` (which run the remote script locally under a temp `HOME`) and pinned globals, as `tests/test_ssh.py` does.

## Names fixed by this plan

- Mirror root: `RMIR = HOME / "Library/Caches/session-deck/remote"` (0700). A host's mirror: `RMIR/<hid>/`, holding `<sid>.jsonl` and `<sid>/subagents/agent-<id>.jsonl|.meta.json`, laid out as in `~/.claude/projects/<dir>/`.
- Server's Claude folder in remote scripts: `C="${CLAUDE_CONFIG_DIR:-$HOME/.claude}"`.
- tmux session options on a remote chat's Mac session (beside Stage 1's `@deck_ssh`): `@deck_claude` (the chat's current session id: set at start, updated when `/clear` changes it), `@deck_rcwd` (server folder), `@deck_rpid` (server pid of Claude once matched), `@deck_rkind` (`tmux` | `plain` | `hand`), `@deck_rcmd` (the remote command string, for reconnect).
- Server-side tmux session for a chat: `deck-<sid>` (status bar off).
- Intervals: transcript sync at most every 1.5 s per chat; server scan (sessions json) cached 3 s per host; automatic reattach tried at most every 30 s per chat.

## Change from the spec (flag to the owner at hand-off)

- Remote chats offer the engines found on the server (`claude`, `rclaude`, `claude-local`), but not the Account choice (`rclaude --account` reads the Mac's plans) or "New git worktree".
- A hand-typed Claude in an SSH terminal is matched to the newest unclaimed live `~/.claude/sessions/*.json` on that server started after the terminal opened. The terminal shows nothing about the cwd, so cwd can't be part of the match.

## Review Focus

1. Two Claude chats on one server started in the same folder seconds apart, or a hand-typed Claude beside a deck-started one, must each show their own transcript and never swap (Task 2 test `test_two_chats_same_folder`).
2. A server transcript that is replaced or shorter than the mirror (`/clear`, compaction) or ends in a half-written line must not corrupt the mirror or the chat view (Task 1 tests `test_shrunk_file_rewritten`, `test_half_line`).
3. When the link drops mid-turn, no "finished" notification fires, the chat says Paused or Disconnected, and reconnecting never starts a second Claude on the same session (Task 3 tests `test_drop_no_push`, `test_reconnect_reuses_session`).
4. A session id, folder or path from the page must never become unquoted shell text or reach outside the server's `$C/projects` and the Mac's `RMIR` (Task 1 `test_bad_names`, Task 3 `test_rfolders_quoted`).
5. A password host with no master, or a slow server, must answer within a few seconds with "open a terminal first" (or a password ask), never stall `/api/sessions` or the watcher (Task 2 `test_no_master_fast`).
